# CLAUDE.md

Рабочие инструкции для Claude Code в этом проекте.

## Контекст

Риск-сводка кредитного портфеля: PostgreSQL (схемы raw и reporting),
семантическая YAML-модель, дашборд на Vega-Lite. Два среза данных:
01.09.2026 и 01.10.2026. Сумма principal_outstanding указана в валюте кредита.

## Жёсткие правила

1. Сырой слой raw не трансформируется. Все поля текстом, загрузка как есть.
   Вся типизация и очистка происходит на входе в reporting.
2. В reporting только CREATE OR REPLACE VIEW. Никаких DROP VIEW в 02_views.sql,
   никаких материализованных таблиц. Повторный запуск любого скрипта ничего не ломает.
3. Определения метрик из задания неприкосновенны:
   портфель без списанных; PAR30/PAR90 строго больше 30/90 дней;
   NPL = просрочка больше 90 ИЛИ реструктуризация;
   провизии 1% / 10% / 50% по бакетам; топ-10 по group_id.
4. Деньги только numeric, никаких float. Округление до копеек один раз,
   производные величины считаются от уже округлённого учётного остатка в тенге.
5. Курс валюты: последний известный на дату среза или раньше. Прямого курса
   на дату может не быть.
6. Каждая новая метрика в витрине получает независимую сверку в 99_checks.sql.
   Сверка считается отдельным простым запросом к raw, без джойна с витриной.
7. Любое изменение SQL прогоняется через ./scripts/run.sh целиком,
   и все сверки должны сойтись в ноль до коммита.

## Команды

```bash
./scripts/run.sh          # полный прогон с сверками
psql $DB -f sql/99_checks.sql   # только сверки
cd dashboard && python3 -m http.server 8000   # дашборд
```

## Чему не верить

Проверять руками за ИИ в первую очередь:
джойны на задвоение строк, NULL в суммах (SUM и FILTER молча их пропускают),
границы дат и строгость неравенств (больше против больше-или-равно),
порядок округления, деление на ноль в долях.
